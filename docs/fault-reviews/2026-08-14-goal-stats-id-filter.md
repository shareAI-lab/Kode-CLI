## 1. 问题描述

### 1.1 问题场景

用户在当前会话中创建多个目标后执行 `/goal stats <goal-id>`。

### 1.2 具体表现

帮助文本声明支持可选 ID，但实现始终把当前会话全部目标传给统计函数，结果总数和状态分布错误。

### 1.3 错误信息

无异常；错误是带 ID 的命令返回了全量统计。

## 2. 临时解决方案

未移除帮助中的 `[goal-id]`，改为实现其既有承诺。

## 3. 根本原因分析

### 3.1 问题分析过程

1. `argumentHint` 和 usage 已包含 `stats [id]`。
2. `stats` 分支未读取 `rest[0]`。
3. 它无条件调用 `sessionGoals(service)`。
4. 因此 ID 只被解析器保留，未参与业务筛选。

### 3.2 直接原因

统计分支遗漏了 `findSessionGoal()` 调用。

**相关代码位置**：`apps/cli/src/commands/builtin/goal.ts:301-320`

### 3.3 根本原因

- **设计层面**：命令帮助与分支行为没有共享参数解析结果。
- **开发层面**：实现统计功能时只覆盖了会话汇总用例。
- **流程层面**：缺少多目标场景下的 ID 定向统计测试。

### 3.4 为什么没有提前发现

- 现有统计测试只调用格式化函数，未执行 slash command 参数路径。
- 单目标会话中全量统计与单目标统计相同。

## 4. 解决方案

### 4.1 根本解决方案

`stats` 读取可选 ID；提供 ID 时仅统计当前会话内该目标，ID 不存在或不属于当前会话时返回明确错误；无 ID 时保持全会话汇总。

**修改文件**：`apps/cli/src/commands/builtin/goal.ts`、`apps/cli/src/commands/builtin/goal.command.test.ts:75-104`

### 4.2 影响范围评估

无 ID 的既有汇总行为不变；带 ID 的输出从错误的全量结果改为单一目标，且不泄露其它会话目标。

## 5. 预防措施

### 5.1 代码层面

- [x] 复用 `findSessionGoal()` 保持 ID 范围校验一致。
- [ ] 对有可选 ID 的子命令抽取统一选择辅助函数。

### 5.2 测试层面

- [x] 增加两个同会话目标时 `stats <id>` 总数为 1 的回归测试。
- [x] 增加不存在 ID 的明确错误断言。

### 5.3 监控层面

- [ ] 无需运行时监控；命令输出由自动化测试覆盖。

### 5.4 流程/规范层面

- [ ] 新增帮助参数时，审查中逐一验证参数在每个分支都被消费。

## 6. 经验总结（一句话）

命令帮助中的每个参数都必须有可验证的实现路径，单目标与全量结果相同的场景不能替代多目标测试。
