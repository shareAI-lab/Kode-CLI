## 1. 问题描述

### 1.1 问题场景

用户完成外部 Codex 登录后立即按 Enter 或 Esc 关闭登录页，而 Kode 的外部运行时模型配置仍在异步保存。

### 1.2 具体表现

界面提示登录完成，但组件卸载会取消后续状态更新；用户可能拥有 Codex CLI 凭据却没有激活可用的 Kode 模型。

### 1.3 错误信息

无异常日志；错误表现是“登录成功”提示与实际主模型配置不一致。

## 2. 临时解决方案

未采用临时绕过。

## 3. 根本原因分析

### 3.1 问题分析过程

1. 登录轮询在认证成功时直接进入 `complete` 状态。
2. 同一个 `complete` 状态触发了异步模型保存，但按键处理同时允许调用 `onDone()`。
3. effect 清理函数把 `cancelled` 设为真，保存前后的检查会直接返回。
4. 因此 UI 完成状态被错误地作为模型激活完成状态使用。

### 3.2 直接原因

认证完成和模型激活完成没有独立的状态机阶段。

**相关代码位置**：`apps/cli/src/ui/components/LoginScreen.tsx:148-215,261-265`

### 3.3 根本原因

- **设计层面**：外部登录副作用与可退出 UI 状态没有定义完成边界。
- **开发层面**：只验证了认证结果，没有验证主模型已持久化。
- **流程层面**：缺少在异步保存未完成时发送退出按键的 UI 回归用例。

### 3.4 为什么没有提前发现

- 代码审查未把 `complete` 既当作认证完成又当作配置完成来检查。
- 原有登录测试未阻塞配置保存后再发送 Enter。

## 4. 解决方案

### 4.1 根本解决方案

新增 `activating` 状态：认证成功后先保存并激活模型，保存成功才进入 `complete`；激活期间吞掉 Enter/Esc。即使组件因其它原因卸载，保存任务仍继续执行，只跳过卸载后的 React 状态更新。

**修改文件**：`apps/cli/src/ui/components/LoginScreen.tsx`、`packages/core/src/test/e2e/tui-interactions.login.test.tsx:34-76`

### 4.2 影响范围评估

仅改变 Codex 登录完成后的交互时序；保存失败进入明确错误状态，成功提示仍保留。

## 5. 预防措施

### 5.1 代码层面

- [x] 将认证完成与配置完成拆分为状态机阶段。
- [x] 把持久化任务与组件的状态更新生命周期分离。

### 5.2 测试层面

- [x] 增加保存未完成时 Enter 不会退出的 Ink 回归测试。

### 5.3 监控层面

- [ ] 后续可记录外部模型激活失败的脱敏诊断事件。

### 5.4 流程/规范层面

- [ ] 审查 OAuth 流程时确认“成功提示”对应全部必需持久化副作用。

## 6. 经验总结（一句话）

认证成功不等于产品可用，依赖认证的模型配置持久化完成前不能给出可退出的成功状态。
